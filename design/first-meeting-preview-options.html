Showing what the first Team Health meeting looks like

A user selects every question in the bank, clicks Start Meeting Series, and still can't picture the meeting. Four ways to show them, from the product owner's modal to a preview that commits to the real draw.

  • 1 question per category per meeting
  • Everything Bagel: 101 questions · 5 categories
  • First draw is uniform random (no history yet)
  • Later draws favor the least-asked question
  • Scheduled series draw when the rrule fires, not on Start
Option A

Sample on Start (the original idea)

Start Meeting Series opens a preview step with one question per category before the schedule dialog.

Your meetings ask 5 questions

One from each category. For example:
  • DependabilityEveryone on this team pulls their weight.
  • ImpactI can see the difference our team's work makes.
  • MeaningI find a sense of personal purpose in my work.
  • Psychological SafetyIt is safe to take a risk on this team.
  • Structure & ClarityOur team has an effective decision-making process.
An example. The first meeting draws its own questions, so they will probably differ.

Where & when

A new first step in the Start dialog, before name/recurrence/calendar.

Data

Client only: the template's questions are already on the page. No server change.

Tradeoffs

  • Cheapest option, and exactly what was asked for
  • Shows up after the user has decided, and adds a click to every start
  • Looks final, but it's a sample. Without the caveat it's misleading, and with it the preview feels hedged
  • A list of questions doesn't show what taking the survey feels like

Effort

~½ day

Where & when

Inline on the Team Health details page, right where questions are selected. The Start flow doesn't change.

Data

Client only: template.questions + category, with the same color order as the meeting. Draws with the same rule the server uses for a first meeting. No new field.

Tradeoffs

  • Answers the question while the user is choosing, before they commit
  • Uses the real card look (category pill, progress, 1–5 scale)
  • Draw again shows that it's a random draw without needing a disclaimer
  • Still a sample. It doesn't promise which questions meeting #1 will use

Effort

~1 day (prototype included)

Option C

Lock in the first draw

The Start dialog shows the draw for meeting #1. The user can reshuffle or swap a category, and those exact questions are sent to the server.

Meeting #1 will ask

  • DependabilityI can count on my teammates to deliver quality work on time.
  • ImpactI understand how our team's work contributes to the organization's goals.
  • MeaningThe work I do for our team is meaningful to me.
  • Psychological SafetyIf I make a mistake on this team, it is not held against me.
  • Structure & ClarityI know what's expected of me, and the goals for my work are clear.
Locked in for the first meeting. After that, questions rotate.

Where & when

Inside the Start dialog, where this is the actual draw.

Data

New firstQuestionIds arg on startTeamHealth, checked on the server (subset of the template, at most one per category). A series scheduled for later creates no meeting on Start, so the draw needs a new MeetingSeries column, or a deterministic seed the client can reproduce.

Tradeoffs

  • True: what the user sees is what the team gets
  • Adds a schema field and a mutation arg, plus edge cases (template edited before the first run, multi-team groups)
  • Swapping questions lets leads cherry-pick, which works against the rotation's even coverage
  • Only helps with meeting #1, not the series

Effort

~3–4 days incl. scheduled-series persistence & tests

Where & when

In the Start sidebar, updated live as teams, questions and cadence change.

Data

Client only: question counts per category. Converting to months needs the cadence, which is only known once the schedule dialog opens.

Tradeoffs

  • Shows why selecting everything is fine (and what it costs): more variety, slower repeats
  • Deterministic, so nothing can mislead

  • Overlaps with the survey-flow animation and the hover summary

Effort

~1 day; its one-line footnote is folded into B's prototype

Recommendation: B, with D's one-line footnote

The confusion happens while questions are being selected, not at Start, so the preview belongs next to the question bank. A sample card with Draw again is honest about the randomness without a disclaimer, and it reuses the real meeting card so users see the survey as their team will. The footnote ("every question comes up within N meetings") answers the next question: what happens when everything is selected.

Keep C in reserve. If users say they need to know exactly which questions meeting #1 will use, the cheapest honest version is a seeded tie-break the server and client share, which avoids a new column. That's worth a separate product decision because it removes the randomness from every series' first meeting.
